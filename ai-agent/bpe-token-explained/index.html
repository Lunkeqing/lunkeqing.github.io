从零讲透 Token 与 BPE：模型是怎么"看"文字的

19 August 2026·2034 words·5 mins
AI Agent Llm Token Bpe 大模型
Author
Lunke
Full-stack engineer passionate about AI Agents and system design. Writing about what I learn and build.

接触大模型的人都绕不开一个词：Token。计费按 token、上下文窗口按 token、性能优化还是围绕 token——它是模型世界的"货币"。

但 Token 到底是什么？为什么教科书说它"不是字也不是词"？背后的 BPE 分词算法又是怎么工作的？

这篇文章不堆公式，用乐高工厂的比喻，带你手把手跑一遍 BPE 的全过程。走完你就懂了。

先给比喻：这其实是个"拆词重组"游戏
#

想象你是乐高工厂的厂长，收到一堆订单（训练语料）。你发现：

  • 订单里 token 这个词出现了 16 次
  • 每次都要拿 5 块小积木（t-o-k-e-n）拼一遍，太累了

于是你决定：把经常一起出现的积木块，提前焊死成一个大积木。以后 token 不用再拼 5 块，直接拿一个成品。

焊死哪些？规则很简单：谁出现得最频繁，先焊谁。焊完再看，继续焊。

这就是 BPE 的全部思想。下面手把手走一遍。

什么是 Token
#

Token（词元）= 模型处理文本的最小单位。

关键认知：它不是"字"，也不是"词"，而是"分词器切出来的片段"。

拿英文举例，unbelievable 可能被切成 un | believ | able 三个 token——因为模型在训练时发现，un-、-able 这些片段经常一起出现，把它们作为独立的积木块更高效。

模型读你的话，不是像人一样一个字一个字看，而是用它的积木块把你的话拆开。这就是为什么同一句话，不同模型的 token 数不一样——它们的积木块（分词器）不同。

手把手演示：用你的语料跑一遍 BPE
#

语料（极度简化，假设模型训练数据里反复出现这些词）：

token    ×8
tokens   ×5
tokenize ×3
hello    ×10

第 0 步：全部拆成单个字符
#

token    → t o k e n
tokens   → t o k e n s
tokenize → t o k e n i z e
hello    → h e l l o

第 1 轮：统计"相邻对"出现次数
#

数一数每两个相邻字符一起出现的次数：

相邻对出现次数来自
t-o8+5+3 = 16token / tokens / tokenize
o-k16同上
k-e16同上
e-n16同上
h-e10hello
e-l10hello
l-l10hello
l-o10hello
n-s5tokens
n-i3tokenize

最高频是 t-o（16 次）→ 焊死，造一个新 token：to

第 2 轮：语料更新后，再统计
#

现在语料变成（用 to 替换所有 t-o）：

token    → to k e n
tokens   → to k e n s
tokenize → to k e n i z e
hello    → h e l l o

再数相邻对：k-e 16 次、e-n 16 次，而 to-k 也是 16 次（现在最高）。

焊死 to-k → tok——注意，to 这个积木又参与了下一轮合并。

第 3、4、5 轮：继续焊
#

token    → tok e n      → 焊死 tok-e → toke
tokens   → tok e n s
tokenize → tok e n i z e
token    → toke n       → 焊死 toke-n → token ✅
tokens   → toke n s     → 焊死 n-s → tokens ✅
tokenize → toke n i z e → 焊死 n-i → tokeni → tokeniz → tokenize ✅

hello 那边同理：h-e → he → hel → hell → hello ✅

最终结果
#

你的词表（从"字符+空格"开始）长出了这些新积木：

token  tokens  tokenize  hello   ← 高频词，一个词一个 token

那它到底是不是"字/词"？
#

都是，也都不是。 关键在"频率"两个字：

  • token、hello 这种高频完整词 → 焊成一个 token（看起来像"词"）
  • to、ke、n 这种中频片段 → 是半个词（看起来像"词根"）
  • i、z、s 这种低频字符 → 单独一个 token（看起来像"字母"）

所以 BPE 出来的 token 没有固定形态，全看语料里什么组合出现得多。这就是教科书说"不是字也不是词，是分词器切出来的片段"的原因。

两个灵魂问题
#

Q：词表为什么不会爆炸？

因为词表大小是设计参数，不是由语料决定的。比如 GPT 系列词表约 10 万，DeepSeek 约 12.8 万。BPE 合并到"词表满了"就停——剩下的低频内容保持字符级。语料再多，词表也不涨。

Q：遇到没见过的生词怎么办？（OOV）

用积木拼！比如语料里没有 tokenizer，但模型遇到它时：

tokenizer → token + ize + r   ← 全是已有积木，拼得出来

这就是 BPE 最牛的地方：模型永远不用"认识"一个词，只需要认识片段。OpenClaw、Transformer、大模型 这种新词，都能用已有积木拼出来。

中文呢？为什么 1 汉字 ≈ 0.6-1 token？
#

中文常用汉字（的、了、是、不……）本身就是高频字符，在 BPE 里通常直接是一个 token，甚至两个常用字（比如"中国"、“我们”）会被焊成一个。

生僻字呢？出现频率低，只能拆成更细的字节级片段 → 可能要 2 个 token。这就是"0.6~1"的来历——常用字不到 1，生僻字超过 1，平均下来接近 1。

⚠️ 顺带提醒：网上很多老文章说"1 汉字 = 1-2 token"，那是 GPT-2 时代英文中心 tokenizer 的旧口径，现代多语言模型已大幅改善。不同模型分词器不同，正确姿势是用各家官方 tokenizer 工具实测，而不是背死一个数。

一句话总结
#

BPE = 反复焊死最高频的相邻片段，直到词表达到目标大小。高频内容变成大积木，低频内容用积木拼，生词永远拼得出来。

理解了 Token 和 BPE，你就掌握了模型世界的"货币"——计费怎么算、上下文窗口怎么估、成本怎么控，全都建立在这个地基上。
